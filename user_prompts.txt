# Autonomous Website QA, Testing & Fix Loop

You are an autonomous senior frontend engineer, QA engineer, UI/UX tester, and browser automation agent.

Your job is to **fully test, diagnose, fix, and re-test this website until there are no known functional, visual, responsive, or interaction issues remaining.**

Do NOT stop after finding issues.  
Do NOT simply report problems.  
**Fix the problems yourself, then re-test them.**

## CORE RULE

Work in a continuous loop:

**DISCOVER → TEST → IDENTIFY ISSUE → FIX → REBUILD/RELOAD → RE-TEST → VERIFY → CONTINUE**

Repeat this process until the entire website has been thoroughly checked.

---

# 1. DISCOVER THE ENTIRE WEBSITE

First, inspect the project and determine:

- All routes/pages
- All accessible pages
- All navigation links
- Header/navigation
- Footer links
- Buttons
- Dropdowns
- Modals
- Forms
- Inputs
- Search functionality
- Tabs
- Accordions
- Carousels/sliders
- Cards with links
- CTAs
- Authentication-related UI
- Settings pages
- Error/empty states
- Loading states
- Pagination
- Filters
- Sort controls
- Tooltips
- Menus
- Mobile navigation
- Any dynamically generated UI
- Any components shared between pages

Also inspect the source code to identify routes/components that may not be reachable through normal navigation.

Create an internal checklist of every page and every interactive element.

---

# 2. TEST EVERY PAGE

Visit **every page individually**.

For each page:

1. Open the page.
2. Wait for it to fully load.
3. Capture/render a screenshot of the page.
4. Inspect the entire visible UI.
5. Scroll from top to bottom.
6. Check for:
   - Broken layouts
   - Overlapping elements
   - Incorrect spacing
   - Incorrect typography
   - Cut-off content
   - Overflow
   - Horizontal scrolling
   - Missing images
   - Broken icons
   - Broken links
   - Incorrect colors
   - Poor contrast
   - Inconsistent components
   - Unexpected blank spaces
   - Loading problems
   - Console errors
   - Network errors
   - JavaScript errors
   - React/framework errors
   - Hydration errors
   - Missing data
   - Incorrect states
   - Broken animations
   - Content extending outside containers

Do not assume that a page is correct just because it loads.

---

# 3. TEST EVERY BUTTON AND INTERACTIVE ELEMENT

For **every button and interactive element**, actually interact with it.

Do not merely inspect the HTML.

For each element:

- Click it.
- Verify the expected behavior.
- Verify navigation if applicable.
- Verify URL changes when applicable.
- Verify modal opening/closing.
- Verify dropdown behavior.
- Verify state changes.
- Verify loading behavior.
- Verify success/error behavior.
- Verify disabled states.
- Verify hover/focus states where applicable.
- Verify keyboard accessibility where applicable.
- Verify that clicking repeatedly does not cause broken behavior.
- Verify that back/close/cancel actions work.

For links:

- Click the link.
- Verify it goes to the correct destination.
- Check for 404s.
- Check for incorrect routes.
- Check for links that do nothing.

For forms:

- Test valid input.
- Test invalid input.
- Test empty input.
- Test boundary cases.
- Submit the form.
- Verify validation messages.
- Verify loading state.
- Verify success state.
- Verify failure state.
- Verify that data is actually processed/persisted where applicable.

If an interaction requires external credentials, payment, email, or another unavailable external dependency, do not fabricate success. Test everything that can be tested locally and clearly record the external dependency.

---

# 4. TEST MOBILE RESPONSIVENESS

Test the entire website on mobile-sized viewports.

At minimum test:

- 320px width
- 375px width
- 390px width
- 414px width

Also test desktop/tablet sizes such as:

- 768px
- 1024px
- 1280px
- 1440px

For every page at every relevant breakpoint, check:

- Layout
- Typography
- Navigation
- Mobile menu
- Buttons
- Forms
- Cards
- Images
- Tables
- Modals
- Dropdowns
- Sticky/fixed elements
- Footer
- Spacing
- Overflow
- Horizontal scrolling
- Touch targets
- Text wrapping
- Content clipping
- Responsive images
- Responsive grids

Pay special attention to issues that only appear after resizing.

---

# 5. VISUAL QA

For every page, render/capture the page and visually inspect it.

Look for:

### Layout
- Misalignment
- Incorrect widths/heights
- Broken grids
- Uneven spacing
- Elements touching each other
- Elements overlapping
- Content outside containers

### Typography
- Wrong font
- Wrong font size
- Wrong line height
- Incorrect weight
- Text clipping
- Unexpected wrapping

### Visual consistency
- Buttons should look consistent.
- Inputs should look consistent.
- Cards should follow the same design system.
- Spacing should be consistent.
- Border radius should be consistent.
- Colors should be consistent.
- Icons should be consistent.

### Images
- Missing images
- Broken image URLs
- Incorrect aspect ratios
- Distorted images
- Images overflowing containers
- Poor mobile behavior

---

# 6. BROWSER / CONSOLE QA

Inspect:

- Browser console
- JavaScript errors
- React errors
- Framework warnings
- Failed network requests
- 404 resources
- 500 responses
- CORS errors
- Missing assets
- Failed API requests
- Hydration errors
- Runtime exceptions

Treat unexpected errors as bugs unless there is a documented reason for them.

---

# 7. ACCESSIBILITY QA

Check:

- Keyboard navigation
- Focus states
- Tab order
- Buttons accessible by keyboard
- Form labels
- Input labels
- Alt text
- Heading hierarchy
- ARIA attributes where appropriate
- Color contrast
- Disabled states
- Modal keyboard behavior
- Escape-to-close behavior
- Screen-reader-friendly semantics where practical
- Touch target sizes on mobile

Fix accessibility issues you discover.

---

# 8. FIX ISSUES YOURSELF

When you discover an issue:

1. Identify the root cause.
2. Modify the source code.
3. Save the changes.
4. Rebuild/restart the application if necessary.
5. Reload the affected page.
6. Reproduce the original problem.
7. Verify that it is fixed.
8. Check that your fix did not break another page/component.

Do NOT just add hacks that hide symptoms.

Prefer fixing the underlying cause.

---

# 9. REGRESSION TESTING

After making a fix to a shared component, **re-test every page that uses that component.**

Examples:

- If you change the header → test every page.
- If you change a button component → test every page containing that button.
- If you change responsive CSS → test desktop and mobile again.
- If you change routing → test all navigation paths.
- If you change forms → re-test all affected forms.

Never assume a fix is isolated.

---

# 10. TEST NAVIGATION AS A USER WOULD

Start from the homepage and navigate through the website naturally.

Test:

Home → Page A → Page B → Page C → Back → Forward → Home

Also test:

- Header navigation
- Footer navigation
- Breadcrumbs
- CTA navigation
- Internal links
- External links
- Browser back button
- Browser forward button
- Direct URL access
- Refreshing pages
- Deep links

Make sure users don't get trapped in broken states.

---

# 11. CHECK EDGE CASES

Look for:

- Empty states
- Long text
- Very short text
- Missing data
- Slow loading
- Failed requests
- Duplicate clicks
- Rapid clicks
- Very narrow screens
- Very wide screens
- Large images
- Long forms
- Invalid URLs
- Refreshing during a state
- Opening/closing modals repeatedly
- Opening multiple dropdowns
- Back navigation after form submission

Fix issues where appropriate.

---

# 12. MAINTAIN A BUG CHECKLIST

Internally maintain something like:

| Page | Element | Issue | Severity | Fixed | Re-tested |
|------|---------|-------|----------|-------|-----------|

Severity:

- P0 = Critical / site unusable
- P1 = Major functionality broken
- P2 = Significant UI/UX issue
- P3 = Minor visual/accessibility issue

Do not mark an issue as fixed until you have actually re-tested it.

---

# 13. IMPORTANT: DO NOT STOP EARLY

Do NOT stop because:

- The homepage looks good.
- The first few pages work.
- There are no obvious errors.
- The build succeeds.
- The console is clean.
- One viewport looks correct.

Continue until:

**EVERY DISCOVERED PAGE → EVERY INTERACTIVE ELEMENT → EVERY IMPORTANT STATE → DESKTOP + MOBILE → HAS BEEN TESTED.**

---

# 14. FINAL VERIFICATION LOOP

Before declaring completion, perform another complete pass.

For every page:

1. Load it.
2. Screenshot/render it.
3. Scroll through it.
4. Test its interactive elements.
5. Check console/network errors.
6. Test responsive behavior.
7. Verify navigation.
8. Verify forms.
9. Verify visual layout.
10. Verify accessibility.
11. Confirm previously fixed bugs remain fixed.

If you find even one issue during the final pass:

**FIX IT → RELOAD → RE-TEST → CONTINUE THE LOOP.**

---

# 15. DEFINITION OF DONE

You may only declare the website complete when:

- All discoverable pages have been tested.
- All important buttons have been tested.
- All links have been tested.
- All forms have been tested.
- All major interactive components have been tested.
- Desktop layouts work.
- Mobile layouts work.
- No unexpected horizontal overflow exists.
- No obvious visual defects remain.
- No unexpected console/runtime errors remain.
- No broken internal navigation remains.
- No broken assets remain.
- Accessibility issues discovered during testing have been fixed.
- Fixes have been regression-tested.
- A final full-site verification pass has been completed.

If something cannot be tested because it depends on an unavailable external service or credential, explicitly identify that limitation instead of pretending it passed.

---

# MOST IMPORTANT INSTRUCTION

**You are not an auditor who only reports bugs. You are an autonomous engineer responsible for fixing them.**

For every bug:

**FIND → UNDERSTAND → FIX → RELOAD → REPRODUCE → VERIFY → REGRESSION TEST**

Keep looping until the website is genuinely in a clean, production-ready state.

Do not ask me to manually check things that you can inspect or test yourself.

Do not stop after producing a bug report.

**Your objective is a working website, not a list of problems.**

### B1 — Hover tooltip galat jagah (tera complaint #1)
- **Cause:** `TimeCharts.jsx` ke dono tooltips `position: 'fixed'; left: clientX; top: clientY` use karte hain, aur ribbon `Card` ke andar hai jisme `backdropFilter: blur(16px)` (Card.jsx). CSS spec me `backdrop-filter`/`filter`/`transform` wala element `fixed` children ka containing block ban jaata hai (WebKit ne bhi isko expected behaviour bola). ### B2 — Ribbon raw entries draw karta hai, stats resolved

## 4. Naya model — math + logic (spec)

### 4.1 Principles
1. **Ek hi source of truth:** `reconcile({plans, entries, nowMin})` → baaki sab UI isi se.
2. **Minute grid (1440):** har minute ka ek actual + ek plan. Overlap = conflict (hide nahi, flag).
3. **Derived, declared nahi:** outcome/flags time-overlap se; user ka input = *reason*.
4. **Unknown ≠ failure:** log nahi = "pata nahi" (tera hi `askModuleAssistant` prompt yehi kehta hai). Adherence sirf *lived & logged* par.
5. **Naam nahi, kind/group:** category ko `group` (same activity?) aur `kind` (score kaise?) do.
6. **Plan snapshot lock** + revisions.

### 4.2 Data model additions (backward-compatible)

```jsonc
// settings.preferences.timeCategories  → objects (purane string list ko migrate)
{ "name": "Waste in Lab 🤬", "group": "waste", "kind": "waste", "level": 0, "color": "#EF4444" }
// kinds: focus(4) · productive(3) · neutral(2) · personal(1) · waste(0) · rest/maintenance(null = pulse se bahar)

// plans[i]
{ "priority": "must|should|nice", "confidence": 0.62, "snapshotAt": "...", "review": { "reason": "overslept" } }

// entries[i]
{ "source": "live-timer|check-in|diary-ai|manual", "confidence": 0.8, "parentId": null, "ghost": false, "reasonTag": "overslept" }
```

### 4.3 Pipeline

```
normalizeDay(entries,date)      // overnight split (summarizeDay ka logic nikaalo)
  → resolveMinutes()            // latest-edited-wins + conflict[] bitmap
  → pass1: run ↔ slot (overlap, phir user ka planSlotId link)
  → pass2: bacha hua slot ko nearest *unclaimed* same-activity run (≤ 8h) = "Shifted"
  → pass3: slot accounting (on / substituted[] / unlogged / future) + flags + causes
  → totals: adherence · completion · conformance · pulse · gaps · swap matrix · drift
```
Full tested code → **Appendix A**.

### 4.4 Formulas

| Metric | Formula | Tere din par |
|---|---|---|
| **Adherence** (kab kiya) | `Σ onPlan ÷ Σ livedPlanned` (planned-waste/buffer slots hata ke) — WFM standard: *minutes in adherence ÷ scheduled minutes* | 41% |
| **Conformance** per group (kitna kiya) | `actual_g ÷ planned_g` (>100% allowed) | Study 21% · Class 46% · Sleep 117% · Talk 267% · Waste 217% · Meals 200% |
| **Completion** (focus) | `Σ min(actual_g, planned_g) ÷ Σ planned_g`, g ∈ focus | 31% |
| **Fidelity** per slot | `on ÷ (L + (runLen − on))` = window ∩ run / window ∪ run (IoU) — late **aur** overrun dono penalise | Sleep 63% |
| **Punctuality** | % slots jinka start `±grace` me; avg lateness = mean(+Δstart) | — |
| **Drift(t)** | `Δstart` har slot ke planned start par → line chart | §2.4 |
| **Pulse** (0–100) | `Σ(level·min) ÷ (4·Σmin)` sirf *discretionary* minutes par (sleep/meals/self-care bahar). RescueTime ka formula: `(vd·0 + d·1 + n·2 + p·3 + vp·4) ÷ (total·4) · 100` | 47 |
| **Weighted adherence** | slot weight `must=3, should=2, nice=1` | optional |
| **Plan realism** | `planned_focus ÷ median(actual_focus, last 14 days)`; >1.3 → "plan zyada hai" | aaj: plan 470 vs actual 90 ⇒ **5.2×** |
| **Estimation accuracy** | `median(actual ÷ planned)` per category, 14 din | trend line |

> **Adherence vs Conformance (industry se):** adherence = *sahi waqt par sahi kaam*, conformance = *kitna kaam hua (waqt ki parwah kiye bina)*. Dono alag dikhao — tera "Study 10:00 ki jagah 12:30 par hui" case conformance me ✅, adherence me ❌ hai. Yehi "real wala scene" hai.

### 4.5 Thresholds (Settings me configurable)

| Param | Default | Matlab |
|---|---|---|
| `grace` | 5 min | ±5 min tak "on time" (WFM tools me bhi 5-min tolerance common hai) |
| `substitutedIf` | ≥ 50% lived | itna hissa doosre kaam ne liya |
| `unloggedIf` | ≥ 50% lived | itna hissa log nahi |
| `maxShift` | 8 h | same activity itni door bhi hui to "Shifted" |
| `minLogCoverage` | 50% of awake lived | isse kam log ⇒ adherence = `null` ("Not enough logs"), 0% nahi |
| `lateEntryHours` | 12 | itni der baad logged ⇒ 🕓 confidence kam |

### 4.6 Flag taxonomy (UI chips)

| Flag | Chip (Hinglish) | Rule |
|---|---|---|
| `ON_TIME` | ✅ On time | `on ≥ 90%` aur `abs(Δstart) ≤ grace` |
| `LATE_START` | ⏰ +60m late | `on>0 && Δstart>grace` |
| `EARLY_START` | ⏩ 90m pehle | `on>0 && Δstart<−grace` |
| `OVERRAN` | 🛌 +120m zyada | `on>0 && Δend>grace` |
| `CUT_SHORT` | ✂️ −60m | `Δend<−grace` aur run `now` se pehle khatam |
| `SHIFTED` | 🔁 12:30 par hui (+2h30) · Δ negative ho to ⏩ *pehle kar liya* | `on=0` + unclaimed same-activity run |
| `SUBSTITUTED` | 🚫 Rishi call ne le liya (60m) | doosre kaam ke minutes ≥ 50% |
| `UNLOGGED` | ❓ Log nahi (pata nahi) | no-log ≥ 50% |
| `PLANNED_WASTE` | 🕳 Buffer / naam batao | kind=waste ya name me "unclear" |
| `IN_PROGRESS` | ▶️ Abhi chal raha | `start ≤ now < end` |
| `UPCOMING` | ⏳ Aane wala | `now < start` |
| `CONFLICT` | ⚠️ 2 logs overlap | conflict bitmap > 0 |
| `PULLED_FORWARD` (cause) | ⏩ baad ka kaam pehle kar liya | intruder run ka owner *baad wala* slot |
| `DELAY_CASCADE` (cause) | ⛓ P3 ke overrun se | intruder run ka owner *pehle wala* slot |

Severity order (primary chip): `UNLOGGED/NEEDS_YOU` > `SUBSTITUTED` > `SHIFTED` > `LATE_START` > `CUT_SHORT` > `OVERRAN` > `EARLY_START` > `ON_TIME`.

### 4.7 Har real case — kaise detect, kaise dikhe, score par asar

| # | Real scene | Detection (minute grid) | Chip / UI | Score effect |
|---|---|---|---|---|
| C1 | Ekdum time par | `on ≥ 90%`, `abs(Δ) ≤ 5` | ✅ | adherence ✔ |
| C2 | Late shuru (Sleep +60) | `Δstart > grace` | ⏰ +60m late | sirf on-plan minutes; punctuality ↓ |
| C3 | Jaldi shuru | `Δstart < −grace` | ⏩ | neutral; agar kisi aur slot ko kha gaya to uspe `PULLED_FORWARD` |
| C4 | Zyada chal gaya (+120 neend) | `Δend > grace` | 🛌 +120m | conformance >100%; victims par `DELAY_CASCADE` |
| C5 | Beech me chhod diya | `Δend < −grace` | ✂️ | on-plan hi |
| C6 | **Same kaam, doosre time (Study 10:00 → 12:30)** | `on=0` + unclaimed run | 🔁 Shifted | **completion ✔, adherence ✘** (missed nahi!) |
| C7 | **Kaam ki jagah kuch aur (Study → Rishi call)** | doosre kaam ke minutes ≥ 50% | 🚫 *Replaced by Rishi (60m)* | adherence 0, swap matrix me entry |
| C8 | Skip + log nahi | no-log ≥ 50% | ❓ pata nahi | adherence se bahar; "coverage" ↓; "Log it" CTA |
| C9 | Split (20m padhai, call, 20m padhai) | slot ke andar ek se zyada matching run | ✂️ 2 parts | on-plan minutes ka sum |

| C12 | Plan me khaali gap me kaam | `plan[i]=null && actual[i]` | 🟣 Unplanned | conformance me nahi, "extra" me |
| C13 | Planned waste / *Unclear* | kind=waste ya "unclear" | 🕳 Buffer ❓ naam batao | adherence se bahar (waste ko reward mat do) |
| C14 | Raat ki neend 23:00→07:00 | midnight par split + `parentId` | ↪ continues | sleep duration = dono ka sum |
| C15 | Abhi chal raha | `s ≤ now < e` | ▶️ + "X/Y min, log nahi ⇒ Start timer" | lived sirf `now` tak |
| C16 | Aane wala | `now < s` | ⏳ | exclude |
| C17 | Overlapping logs | conflict bitmap | ⚠️ **resolver:** "01:00–02:00: Talk (00:00–02:00) vs Waste (01:00–02:00) — kaunsa sahi?" | resolve hone tak latest-edited, chip dikhe |
| C18 | Plan baad me badla | `updatedAt > snapshotAt` | 🔒 Plan 14:10 par badla | adherence snapshot par |
| C19 | Label shak wala | name vs slot vs ghadi ("Lunch" 19:00 jabki plan Dinner); name me "waste" par kind≠waste | 🏷 Label check? | suggestion, auto-change nahi |
| C20 | Agle din log kiya | `createdAt − end > 12h` | 🕓 late entry | confidence ↓ |
| C21 | AI se aaya | `source=diary-ai` | 🤖 verify | confidence ↓ |

| C23 | Pattern (7 din) | same group×hour-band ≥ 4/7 skip | 🔁 "Shaam ki study 5/7 din skip" | insights |
| C24 | Timezone/travel | `plan.timezone ≠ profile` | 🌍 | plan ke tz me now/day-boundary |
| C25 | Wapas track par | lag +120 → fir ≤ grace | 🎯 "16:50 par recover" | positive streak |
| C26 | Zyada kiya | `actual_g > planned_g` | 🔥 +30m extra | conformance >100% |

### 4.8 Cause / cascade (kyun hua?)
- Har substitute run ka **owner** = wo plan slot jisne us run ko claim kiya.
- Owner *pehle* ka slot ⇒ `DELAY_CASCADE` ("⛓ P3 ke overrun ne P4, P5 ko khaya"). Owner *baad* ka slot ⇒ `PULLED_FORWARD` ("Dinner & Rishi call pehle ho gaye, study kha gaye").
- UI me sirf **pehla-level cause** dikhao; "root" (chain ka sirf starting slot) ek line me ("Din 02:00 ki neend se ~2h peeche chala"). Poore chain ko "cost" mat bolo — double-counting hoti hai (P3→…→P12 chain 340 min bolega jo asal me ek hi delay ka shadow hai).

### 4.9 Missing / ambiguous data ke rules
- Past din, logs nahi ⇒ `adherence = null`, UI: "Is din ka log nahi — [Diary photo] [Quick log]".
- Entry me `end ≤ start` (legacy overnight) ⇒ normalize; kabhi silently 1440 tak mat kaato.
- AI confidence < 0.6 ya `Unclear` ⇒ save se pehle ❓ confirm.

```jsx
import { createPortal } from 'react-dom'
import { useEffect, useLayoutEffect, useRef, useState } from 'react'

/** point = {x,y} in viewport px (clientX/Y). Portal ⇒ backdrop-filter/transform ancestors ka asar nahi. */
export default function HoverCard({ point, children, interactive = false, onDismiss }) {
  const ref = useRef(null)
  const [pos, setPos] = useState({ left: -9999, top: -9999 })
  useLayoutEffect(() => {
    if (!point || !ref.current) return
    const { width: w, height: h } = ref.current.getBoundingClientRect()
    const vw = window.innerWidth, vh = window.innerHeight, pad = 8, gap = 14
    let left = point.x + gap, top = point.y - h - gap
    if (left + w > vw - pad) left = point.x - w - gap       // right edge: flip left
    if (left < pad) left = pad
    if (top < pad) top = point.y + gap                        // top edge: flip below
    if (top + h > vh - pad) top = vh - h - pad
    setPos({ left, top })
  }, [point?.x, point?.y, children])
  useEffect(() => {
    const onKey = (e) => e.key === 'Escape' && onDismiss?.()
    window.addEventListener('keydown', onKey); return () => window.removeEventListener('keydown', onKey)
  }, [onDismiss])
  if (!point) return null
  return createPortal(
    <div ref={ref} role="tooltip" style={{ position: 'fixed', ...pos, zIndex: 10000, pointerEvents: interactive ? 'auto' : 'none',
      background: 'rgba(15,23,42,.97)', border: '1px solid rgba(148,163,184,.2)', borderRadius: 12, padding: '10px 12px',
      boxShadow: '0 12px 32px rgba(0,0,0,.5)', color: '#F8FAFC', fontSize: 12, maxWidth: 280 }}>{children}</div>,
    document.body)
}
```

## Appendix A — Reference engine (`src/utils/timeModel.js`) — **tested on your day**

> Pure functions, React nahi. Assumption: `entries` pehle `normalizeDay()` se overnight-split ho chuke hon. `groups/kinds` ko Settings ke category objects se build karo.
>
> **Implemented:** minute-grid resolve, 3-pass matching, flags, causes, adherence, completion, pulse, gaps, conflict minutes. **Tu add karega (spec §4.5/§4.9):** `minLogCoverage` (adherence `null`), `lateEntryHours`/`confidence`, planned-`Unclear` rule, priority weights, plan snapshot.

```js
// reconcile.mjs — reference implementation (pure functions, no React)
const tm = (v) => (v === '24:00' ? 1440 : (([h, m]) => h * 60 + m)(v.split(':').map(Number)))
export const hhmm = (m) => `${String(Math.floor(m / 60) % 24).padStart(2, '0')}:${String(m % 60).padStart(2, '0')}`

// ── 1. category → group (what counts as "the same activity") and kind (how it is scored)
export const DEFAULT_GROUP = { 'Morning Routine': 'selfcare', 'Self-Care': 'selfcare', 'Waste Time': 'waste', 'Social Media': 'waste', 'Entertainment': 'waste', 'Waste in Lab': 'waste' }
export const DEFAULT_KIND = {  // level 0..4 like RescueTime's pulse
  Study: { kind: 'focus', level: 4 }, 'Deep Work': { kind: 'focus', level: 4 }, Class: { kind: 'focus', level: 4 },
  Exercise: { kind: 'productive', level: 3 }, 'Talk with Dost': { kind: 'social', level: 2 },
  Sleep: { kind: 'rest', level: null }, Meals: { kind: 'maintenance', level: null },
  'Self-Care': { kind: 'maintenance', level: null }, 'Morning Routine': { kind: 'maintenance', level: null },
  'Waste Time': { kind: 'waste', level: 0 }, 'Waste in Lab': { kind: 'waste', level: 0 },
  'Social Media': { kind: 'waste', level: 0 }, Entertainment: { kind: 'waste', level: 0 },
}
export const groupOf = (c, map = DEFAULT_GROUP) => map[c] || c
export const kindOf = (c, map = DEFAULT_KIND) => map[c] || (/waste|time\s?pass|scroll/i.test(c || '') ? { kind: 'waste', level: 0 } : { kind: 'neutral', level: 2 })

// ── 2. one minute-by-minute truth (latest edited wins, conflicts remembered)
export function resolveMinutes(entries) {
  const mins = new Array(1440).fill(null), conflict = new Array(1440).fill(false)
  const sorted = [...entries].sort((a, b) => String(a.updatedAt || a.createdAt || '').localeCompare(String(b.updatedAt || b.createdAt || '')))
  for (const e of sorted) { const s = tm(e.start), en = tm(e.end); if (!(en > s)) continue; for (let i = s; i < en; i++) { if (mins[i]) conflict[i] = true; mins[i] = e } }
  return { mins, conflict }
}
export const runsOf = (mins, pred) => { const out = []; let cur = null
  for (let i = 0; i < 1440; i++) { const hit = mins[i] && pred(mins[i]); if (hit && !cur) cur = { start: i, end: i + 1 }; else if (hit) cur.end = i + 1; else if (cur) { out.push(cur); cur = null } }
  if (cur) out.push(cur); return out }

// ── 3. reconcile plan vs actual
export function reconcile({ plans, entries, nowMin = 1440, grace = 5, maxShift = 480, kinds = DEFAULT_KIND, groups = DEFAULT_GROUP }) {
  const { mins, conflict } = resolveMinutes(entries)
  const G = (c) => groupOf(c, groups)
  const sortedPlans = [...plans].sort((a, b) => tm(a.start) - tm(b.start))
  const ov = (r, s, e) => Math.max(0, Math.min(e, r.end) - Math.max(s, r.start))

  // PASS 1 — which actual run "belongs" to which plan slot (overlap first, then the user's own link)
  const runsByGroup = {}; const owner = new Map()            // run.start+group -> slot id
  const runsFor = (g) => (runsByGroup[g] ||= runsOf(mins, (a) => G(a.category) === g))
  const pick = new Map()                                      // slot id -> run
  const claim = (slot, run, g) => { pick.set(slot.id, run); const k = g + run.start; const prev = owner.get(k); if (!prev || ov(run, tm(slot.start), tm(slot.end)) > ov(run, tm(prev.start), tm(prev.end))) owner.set(k, slot) }
  sortedPlans.forEach((p) => {
    const g = G(p.category), s = tm(p.start), e = tm(p.end), runs = runsFor(g)
    const best = [...runs].sort((x, y) => ov(y, s, e) - ov(x, s, e))[0]
    if (best && ov(best, s, e) > 0) return claim(p, best, g)
    const i = mins.findIndex((a) => a && a.planSlotId === p.id && G(a.category) === g)
    const lr = i >= 0 && runs.find((r) => i >= r.start && i < r.end)
    if (lr) claim(p, lr, g)
  })
  // PASS 2 — slots still without a run may take the nearest UNCLAIMED run of the same activity (= "done at another time")
  sortedPlans.forEach((p) => {
    if (pick.has(p.id)) return
    const g = G(p.category), s = tm(p.start)
    const free = runsFor(g).filter((r) => !owner.has(g + r.start) && Math.abs(r.start - s) <= maxShift)
      .sort((x, y) => Math.abs(x.start - s) - Math.abs(y.start - s))[0]
    if (free) claim(p, free, g)
  })

  // PASS 3 — minute accounting + flags per slot
  const slots = sortedPlans.map((p) => {
    const s = tm(p.start), e = tm(p.end), L = e - s, g = G(p.category), run = pick.get(p.id) || null
    let on = 0, unl = 0, fut = 0; const subs = new Map()
    for (let i = s; i < e; i++) {
      const a = mins[i]
      if (!a) { i >= nowMin ? fut++ : unl++; continue }
      if (G(a.category) === g) on++
      else { const k = subs.get(a.id) || { id: a.id, name: a.name, category: a.category, min: 0 }; k.min++; subs.set(a.id, k) }
    }
    const pastL = L - fut, runLen = run ? run.end - run.start : 0, sd = run ? run.start - s : null, ed = run ? run.end - e : null
    const subMin = [...subs.values()].reduce((a, b) => a + b.min, 0), kind = kindOf(p.category, kinds).kind, flags = []
    if (pastL <= 0) flags.push('UPCOMING')
    else {
      if (s <= nowMin && e > nowMin) flags.push('IN_PROGRESS')
      if (on === 0 && run) flags.push('SHIFTED')                      // done, but in another window
      if (on > 0 && sd > grace) flags.push('LATE_START')
      if (on > 0 && sd < -grace) flags.push('EARLY_START')
      if (on > 0 && ed > grace) flags.push('OVERRAN')
      if (on > 0 && ed < -grace && run.end < nowMin) flags.push('CUT_SHORT')
      if (subMin >= pastL * 0.5) flags.push('SUBSTITUTED')
      if (unl >= pastL * 0.5) flags.push('UNLOGGED')
      if (!flags.some((f) => f !== 'IN_PROGRESS')) flags.push('ON_TIME')
    }
    const fidelity = pastL <= 0 ? null : on > 0 ? Math.round((on / (L + (runLen - on))) * 100) : 0
    return { id: p.id, name: p.name, category: p.category, start: p.start, end: p.end, kind, minutes: L, lived: pastL, on, unl, fut,
      subs: [...subs.values()].sort((a, b) => b.min - a.min), run: run && { start: hhmm(run.start), end: hhmm(run.end) },
      startDelta: sd, endDelta: ed, fidelity, flags, countsInAdherence: kind !== 'waste' && pastL > 0, causes: [] }
  })
  // WHY: who stole my slot? (intruder run belongs to an earlier slot ⇒ overrun/delay cascade; to a later slot ⇒ pulled forward)
  const byId = Object.fromEntries(slots.map((x) => [x.id, x]))
  slots.forEach((x) => x.subs.forEach((sb) => {
    const idx = mins.findIndex((a) => a && a.id === sb.id); const run = runsFor(G(sb.category)).find((r) => idx >= r.start && idx < r.end)
    const o = run && owner.get(G(sb.category) + run.start)
    if (o && o.id !== x.id) x.causes.push({ slotId: o.id, name: o.name, min: sb.min, type: tm(o.start) < tm(x.start) ? 'DELAY_CASCADE' : 'PULLED_FORWARD' })
  }))
  const rootOf = (id, seen = new Set()) => { const c = byId[id]?.causes.filter((k) => k.type === 'DELAY_CASCADE').sort((a, b) => b.min - a.min)[0]; return c && !seen.has(c.slotId) ? rootOf(c.slotId, seen.add(id)) : id }
  slots.forEach((x) => { x.root = x.causes.some((k) => k.type === 'DELAY_CASCADE') ? rootOf(x.id) : null })

  const counted = slots.filter((x) => x.countsInAdherence)
  const lived = counted.reduce((a, x) => a + x.lived, 0), onSum = counted.reduce((a, x) => a + x.on, 0)
  const byGroup = {}
  slots.forEach((x) => { (byGroup[G(x.category)] ||= { planned: 0, actual: 0 }).planned += x.lived })
  mins.forEach((a, i) => { if (a && i < nowMin) (byGroup[G(a.category)] ||= { planned: 0, actual: 0 }).actual++ })
  const focus = Object.entries(byGroup).filter(([g]) => kindOf(g, kinds).kind === 'focus')
  const fp = focus.reduce((a, [, v]) => a + v.planned, 0), fd = focus.reduce((a, [, v]) => a + Math.min(v.planned, v.actual), 0)
  let pm = 0, pw = 0; mins.forEach((a, i) => { if (!a || i >= nowMin) return; const lv = kindOf(a.category, kinds).level; if (lv == null) return; pm++; pw += lv })
  const gaps = runsOf(mins.map((a, i) => (a ? null : { i })), () => true).filter((r) => r.start < nowMin).map((r) => ({ start: hhmm(r.start), end: hhmm(Math.min(r.end, nowMin)), min: Math.min(r.end, nowMin) - r.start }))
  return { slots, byGroup, gaps, conflictMins: conflict.filter(Boolean).length,
    adherence: lived ? Math.round((onSum / lived) * 100) : null, completionFocus: fp ? Math.round((fd / fp) * 100) : null,
    pulse: pm ? Math.round((pw / (4 * pm)) * 100) : null, discretionaryMin: pm }
}
```
